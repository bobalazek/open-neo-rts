# Content pipeline and validation

Every unit, structure, faction, map and asset (with the weapons, abilities and research defined inline in units and structures) is described by metadata and checked automatically. Broken or stale content can't reach `main`.

## Metadata for everything

- **Definitions are JSON**, one file per definition, each with a `$schema` reference for editor autocomplete and inline errors. (JSON over YAML: one format, native in Bun and browsers, and the best schema tooling.)
- **Schemas** live in `content/schemas/`. They're generated by `bun neo generate-schemas` from the definitions in `packages/content/src/schemas/`, so code and schema never drift apart; CI fails when they're stale.
- Every definition has an `id` matching its folder and an English `name` and `description`; units and structures also have a `role` and a `presentation` (model, icon, sounds), plus their kind-specific fields ([content-format.md](../contributing/content-format.md)). Translations are separate, in the pack's `locales/<lang>.json`.
- Every asset folder has an `assets.json` with each file's author and editable source ([assets.md](../contributing/assets.md)).
- **Models declare their parts:** a unit's `presentation.parts` lists the node names the sim and renderer use (`hull`, `turret`, `barrel`, `rotor`, `legs`), and the GLB must contain exactly those nodes. Attachment points such as `socket_muzzle` are sockets, listed in `presentation.sockets` ([assets.md](../contributing/assets.md#model-conventions)).

## Checks

`bun neo validate-content` (definitions and models against them) and `bun neo validate-assets` (files and provenance) run locally, and `bun neo validate` (both, plus the schema freshness check) runs in CI on every PR that touches content.

**Definitions:**

| Check      | Catches                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Schema     | Missing or wrong fields, wrong types, floats where integers are required                                                        |
| References | Unknown IDs (units, structures, research, translations of missing definitions, assets)                                          |
| Graphs     | Tech-tree cycles, unreachable techs, units nobody can build, campaign missions nobody can unlock                                |
| Uniqueness | Duplicate IDs across packs, hotkey conflicts within a command card                                                              |
| Rules      | Footprints that fit the grid, a population cost on every unit, exactly one headquarters per faction and a builder trained there |
| Locales    | Missing translations (warning), unused keys (warning)                                                                           |
| Eras       | Every definition valid for each era it claims; per-era overrides reference existing assets                                      |

**Assets:**

| Check            | Catches                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| glTF conformance | Unreadable or invalid GLB files (Khronos glTF validator)                                                                                                |
| Structure        | Required part nodes present and named as declared; origin at ground centre; Y-up; scale in metres within the expected bounds for its footprint          |
| Budgets          | Triangle counts, LOD count, texture sizes, material count (palette material only)                                                                       |
| Animations       | Clip names match what the definition references; skeletons within joint and influence limits                                                            |
| Provenance       | Every file has an `assets.json` entry                                                                                                                   |
| Runtime audio    | Complete checksummed Ogg pages, one Vorbis/Opus stream, mono unit/structure/prop effects, successful decoding, non-silent output and true-peak headroom |
| Formats          | Allowed extensions only; binaries tracked by Git LFS                                                                                                    |

**Staleness:**

| Check               | Catches                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------- |
| Orphans             | Asset files no definition references                                                        |
| Missing             | Definitions pointing at files that don't exist                                              |
| Dead provenance     | `assets.json` entries for deleted files                                                     |
| Out-of-date exports | A `source/` file newer than its exported runtime asset (warning)                            |
| Generated files     | Schemas, the balance report and the Field Manual index are up to date (regenerate and diff) |

## Previews and reports

- The validator writes a machine-readable report, which CI posts as a PR comment along with debug mode preview links ([CONTRIBUTING.md](../../CONTRIBUTING.md#previews)).
- Turntable thumbnails of changed models are rendered headlessly and attached to the comment (later).

## Implementation

- `packages/content` holds the types, the generated schemas, a loader that resolves packs and dependencies, and the validators. These are our own, per [build vs. use](architecture.md#build-vs-use).
- `resolvePacks` accepts parsed pack files and runtime bytes without file I/O. It validates manifests and definitions, resolves required and present optional dependencies in stable ID order, checks versions/conflicts/cycles, and returns qualified definition IDs plus gameplay/cosmetic identity. CLI validation uses this same catalog before model checks. Invalid inputs and expected-hash mismatches throw `PackResolutionError` instead of returning a partially usable catalog.
- Gameplay identity excludes labels, presentation and team colour, includes map-layer bytes and dependency scope, and is unchanged by locale-only packs. Cosmetic identity includes full definitions, manifests and referenced presentation assets. Source files and provenance are outside runtime identity. Identities reuse the deterministic 64-bit hasher for accidental mismatch detection; they are not authentication or hostile-file integrity signatures. Definitions are private frozen JSON snapshots; gameplay-unit conversion is separate work.
- `compileGameplayCatalog` converts validated raw definitions into integer gameplay inputs: subcells, ticks, per-mille modifiers and explicit rate quantities. It reuses the existing spawn definition conversion and dependency reference order. Missing headquarters/extractor construction prices and times remain unavailable recipes; omissions cannot become free or instant builds. CLI content validation runs compilation before model validation. Compilation supplies data to later economy/combat systems; it does not implement those systems or make the whole roster playable.
- The browser preview registry reads unit/structure/prop paths from the validated core manifest. It still permits unavailable LFS artwork and does not claim full match identity. A real match loader must supply actual runtime bytes to `resolvePacks`; missing bytes cannot produce a trusted catalog. Shared resolution and mismatch refusal are checked in Bun and browsers.
- **glTF conformance** uses the official Khronos validator (tooling, not a game dependency). Our own checks for parts, budgets and clips read the GLB with a small parser in `packages/content`.
- **Audio** uses a small Ogg framing/checksum check and the installed FFmpeg decoder/EBU R128 meter in CLI tooling. FFmpeg is required on `PATH` when runtime Ogg clips are present; CI installs it for tooling tests and content validation. Source originals are excluded from runtime format/provenance checks. Full-mix/category loudness qualification remains part of the music/announcer work.
- The same validators run in the map editor, in the game when loading mods, and on the server when accepting custom content.

The normal browser build adapter reads the full original core inventory, resolves
real gameplay/cosmetic identity and emits only the compiled integer catalog.
Raw binary bytes stay out of JavaScript. Incomplete LFS installs produce an explicit
unavailable-content result, preserving Home/debug while normal Start refuses.
Browser CI pulls the full original core content before building this catalog.
