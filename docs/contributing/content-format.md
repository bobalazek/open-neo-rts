# Content format

All game content is JSON data plus assets, in **packs**. This page explains the layout, IDs, units of measure, and what each kind of file contains. Naming rules are in [conventions.md](conventions.md); adding a unit step by step is in [adding-content.md](adding-content.md).

## Layout

```text
content/
├── schemas/                              generated by `bun neo generate-schemas`; never edited by hand
└── core/                                 the base game (a pack)
    ├── manifest.json                     lists every definition file in the pack
    ├── locales/                          translations only, <lang>.json (none yet)
    ├── factions/
    │   └── <faction>/                    alliance-of-free-nations, eastern-collective, phoenix-initiative
    │       ├── faction.json              name, colour, start kit, bot personality
    │       ├── units/<name>/             unit.json + model, wreck, icon, sounds, assets.json
    │       └── structures/<name>/        structure.json + model, rubble, icon, sounds, assets.json
    ├── neutral/structures/<name>/        faction-agnostic structures: tech buildings, the Quantum Nexus wonder
    ├── props/<biome>/<name>/             map objects: trees, rocks, ruins (prop.json + model; none yet)
    └── maps/<name>/                      map.json + terrain layers + preview
```

- **One folder per thing.** A unit's folder holds its definition, with weapons, abilities and English strings **inline**, next to its model, icon and sounds. A structure's folder also holds the research it offers.
- **What isn't content:** resources, armour classes, projectile and warhead kinds, unit and structure **roles**, and match settings are engine code in `packages/content/src/rules/` ([decision](../project/decisions/2026-11-01-content-model.md)).
- **Mods** are more packs next to `core` (`content/<mod>/`), with the same layout ([modding.md](../engineering/modding.md)).

## Manifest

Node-bound structures declare `nodeKinds`, a nonempty list of `materials` and/or `oil`, separately from their ordinary footprint `cells` terrain rules. `extractor` is the shared producer role. Its debug placement must match a specific node anchor and may ignore only that exact node's resource occupancy. Node markers in maps use `kind: materials` with a required `amount`, or `kind: oil` with an optional amount until depletion is decided. Only ore fields may declare a radius. Phase-1b extractor content intentionally omits cost, build time and yield; a later normal-match compiler must require an approved economy contract rather than treating omissions as free/instant production.

The loader never scans folders: `manifest.json` lists every definition file, and `bun neo validate` fails on a listed file that's missing and on a JSON file that isn't listed.

```json
{
  "$schema": "../schemas/manifest.schema.json",
  "id": "core",
  "version": "0.1.0",
  "engine": ">=0.1.0",
  "name": "Core",
  "description": "The base game.",
  "dependencies": {},
  "files": {
    "factions": ["factions/eastern-collective/faction.json"],
    "units": ["factions/eastern-collective/units/dragon-tank/unit.json"],
    "structures": ["factions/eastern-collective/structures/war-factory/structure.json"],
    "maps": ["maps/training-grounds/map.json"]
  }
}
```

**Versions and compatibility:** `version` (semver) and `engine` (supported range); `dependencies`, `optionalDependencies` and `conflicts` with version ranges; `"gameplay": false` for packs that only change looks or text, which don't need to match in multiplayer. Saves and replays record every pack's ID, version and hash.

## IDs

IDs follow folders, so they're unique and readable:

| Kind              | ID                                         | Folder                                                |
| ----------------- | ------------------------------------------ | ----------------------------------------------------- |
| Faction           | `faction:eastern-collective`               | `factions/eastern-collective/`                        |
| Unit              | `unit:eastern-collective/dragon-tank`      | `factions/eastern-collective/units/dragon-tank/`      |
| Structure         | `structure:eastern-collective/war-factory` | `factions/eastern-collective/structures/war-factory/` |
| Neutral structure | `structure:neutral/quantum-nexus`          | `neutral/structures/quantum-nexus/`                   |
| Prop              | `prop:temperate/oak-tree`                  | `props/temperate/oak-tree/`                           |
| Map               | `map:training-grounds`                     | `maps/training-grounds/`                              |

Another pack's content is referenced as `<pack>.<id>` (`core.unit:eastern-collective/dragon-tank`). Weapons, abilities and research are inline, with local names (`"id": "heavy-cannon"`).

## Units of measure

Data uses **human units**; the loader converts them to integer sim units once ([numerics.md](../engineering/numerics.md#content-units)).

| Field kind                              | Unit                          | Example                        |
| --------------------------------------- | ----------------------------- | ------------------------------ |
| Distance, range, radius, vision         | cells (2 m), decimals allowed | `"range": [0, 6]`              |
| Speed                                   | cells per second              | `"speed": 1.8`                 |
| Time: build, reload, cooldown, duration | seconds                       | `"reload": 2.5`                |
| Turn rate                               | degrees per second            | `"turnRate": 80`               |
| Multipliers                             | percent, integer              | `"versus": { "infantry": 25 }` |
| Costs, health, damage                   | integers                      | `"health": 900`                |

## Unit

Every unit has a **`role`** the engine understands (`builder`, `harvester`, `combat`, `scout`, `support`, `transport`), whatever the faction calls it.

```json
{
  "$schema": "../../../../../schemas/unit.schema.json",
  "id": "unit:eastern-collective/dragon-tank",
  "name": "Dragon Tank",
  "description": "Heavy main battle tank that switches between assault and siege mode.",
  "role": "combat",
  "family": "vehicle",
  "tags": ["vehicle"],
  "cost": { "credits": 1000, "materials": 100 },
  "buildTime": 15,
  "producedBy": ["structure:eastern-collective/war-factory"],
  "health": 900,
  "armor": "heavy",
  "resist": { "fire": 75 },
  "movement": { "domain": "tracked", "speed": 1.8 },
  "radius": 0.85,
  "vision": 8,
  "pop": 3,
  "turret": { "turnRate": 80 },
  "weapons": [
    {
      "id": "heavy-cannon",
      "targets": ["ground", "structure"],
      "range": [0, 7],
      "reload": 3,
      "accuracy": 0.2,
      "aim": "turret",
      "projectile": { "kind": "bullet", "speed": 20, "blockedBy": ["terrain", "structures"] },
      "warheads": [
        {
          "type": "damage",
          "amount": 90,
          "versus": { "default": 100, "infantry": 30, "aircraft": 0, "structure": 80 },
          "tags": ["explosive"]
        },
        {
          "type": "damage",
          "amount": 15,
          "radius": 0.5,
          "falloff": [100, 50],
          "versus": { "default": 0, "infantry": 100 },
          "tags": ["explosive"]
        }
      ]
    }
  ],
  "abilities": [
    {
      "id": "siege-mode",
      "name": "Siege Mode",
      "description": "Deploys: +50% range and +25% damage, but can't move.",
      "target": "self",
      "cooldown": 3,
      "effects": [
        { "type": "modifyStat", "stat": "range", "percent": 150, "scope": "self" },
        { "type": "modifyStat", "stat": "damage", "percent": 125, "scope": "self" }
      ]
    }
  ],
  "presentation": {
    "model": "dragon-tank.glb",
    "icon": "dragon-tank.icon.png",
    "wreck": "dragon-tank.wreck.glb",
    "materials": {},
    "parts": ["hull", "turret", "barrel"],
    "sockets": ["socket_muzzle", "socket_exhaust", "socket_smoke"],
    "animations": []
  }
}
```

Weapons follow launcher → projectile → warheads, with `versus` per armour class on each damage warhead ([combat-and-balance.md](../design/combat-and-balance.md)). Builders construct, repair and capture through their role; what they may repair is set by `repair` (below).

## Structure

Structures have a **`role`** too (`headquarters`, `power`, `dropoff`, `production`, `research`, `support`, `defense`, `wall`, `superweapon`, `wonder`). Any builder of the faction constructs them, so they have no `producedBy`.

| Field                                    | Meaning                                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `footprint`, `cells`                     | Size in cells, and optionally a row per depth of cell rules (`l` land, `s` shore, `w` water) for coastal structures |
| `power`                                  | + produced, − used                                                                                                  |
| `weapons`, `abilities`                   | Inline, as for units                                                                                                |
| `research`                               | Upgrades and techs researched here, inline                                                                          |
| `spawnsWith`, `dock`, `pads`, `garrison` | A free unit on completion, a harvester dock, aircraft pads, infantry slots                                          |
| `adjacency`                              | Bonuses to nearby structures with given tags                                                                        |
| `requires`                               | Structures or research needed before it can be built                                                                |

## Repair, healing and other targeted effects

Who can repair or heal what is data, on the ability or the role:

```json
"repair": { "targets": { "families": ["vehicle"], "roles": ["combat", "harvester"], "tags": [] }, "rate": 10, "costPercent": 25 }
```

- `targets` filters by `families`, `roles` and `tags` (all optional; empty means any).
- `rate` is health per second; `costPercent` is the share of the target's cost charged for full repair.
- Builders repair structures by default. A unit or structure with `repair` (a Recovery Vehicle, a Medical Bay) repairs what its filter allows.

## Presentation

| Field                            | Meaning                                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`, `wreck`, `icon`         | File names in the same folder                                                                                                                                                         |
| `materials`                      | Map from the model's material names to slots, when they aren't named after slots                                                                                                      |
| `parts`, `sockets`, `animations` | What the model must contain; checked by `bun neo validate`                                                                                                                            |
| `damageStates`                   | Health thresholds for visual states, e.g. `[{ "below": 66, "show": "state_damaged", "effects": ["smoke"] }, { "below": 33, "show": "state_critical", "effects": ["smoke", "fire"] }]` |
| `construction`                   | Build-up animation: `bricks` (assemble layer by layer, default), `drop` (lowered in), `unfold` (for deployables)                                                                      |
| `destruction`                    | `explode` (brick burst, default for vehicles), `collapse` (top-down, default for structures), `sink` (ships), `crash` (aircraft); with `size`: `small`, `medium`, `large`, `huge`     |
| `sounds`                         | Event → file: `fire`, `move`, `select`, `death`…                                                                                                                                      |

## Faction, map and props

- **Faction:** name, description, colour, start kit (headquarters, builders, harvester, infantry, credits), bot personality. Example: `factions/eastern-collective/faction.json`.
- **Map:** size, biome, player count, spawns with facing, suggested team layouts, start mode, resource fields, pre-placed objects, terrain layers ([authoring-scenarios.md](authoring-scenarios.md#skirmish-maps)).
- **Prop:** footprint, whether it blocks movement or vision and for which movement domains, destructible or crushable, harvestable (e.g. wood).

## Translations

English is written in the definitions. Other languages go in `locales/<lang>.json`, keyed by definition ID and field:

```json
{ "unit:eastern-collective/dragon-tank.name": "Drachenpanzer" }
```

Interface strings live in the client code ([localization.md](../engineering/localization.md)).

## Schemas and validation

- Schemas are defined once in `packages/content/src/schemas/definitions.ts`; `bun neo generate-schemas` writes them to `content/schemas/`, and CI fails when they're stale. Every definition's `$schema` points at its schema, so editors autocomplete as you type.
- `bun neo validate` checks: manifests; `$schema` paths; schema validity (unknown fields count as typos); IDs matching folders; every reference resolving; roles present (exactly one headquarters per faction, and a builder trained there); each referenced asset existing; and each model against its definition (parts, a socket per weapon, clips, material map, size).
- Maps are checked for layer sizes and values, ramps (rising exactly one level, at least 2 cells wide), a shallow band between deep water and land, and spawns, resources and objects at least 4 cells from the map edge.
