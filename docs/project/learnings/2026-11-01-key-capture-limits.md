The probe at `apps/web/e2e/key-capture.html` records events delivered to its surface and focused input, including `cancelable`, `defaultPrevented`, `isTrusted` and fullscreen/pointer-lock state. Playwright describes its API as a virtual keyboard that generates page events. **Inference:** delivery and even `isTrusted: true` through that path do not establish native browser/OS accelerator interception. Native verification remains required for F1/F3/F5/F11/F12, Ctrl/Cmd+W/T/N/L/R/Q, Ctrl+0–9 browser-shortcut conflicts, modifier+F1–F4, and short/held Escape while fullscreen/locked. This probe does not choose fallback bindings. [Playwright keyboard API](https://playwright.dev/docs/api/class-keyboard)

Keyboard Lock captures only keys allowed by the host OS; Chrome documents JavaScript-initiated fullscreen as its prerequisite. Feature detection, permission query and request outcomes are recorded separately. Chrome's permission article now carries a withdrawal warning, so browser version alone is not evidence that a particular prompt/grant policy applies. [Keyboard Lock draft](https://wicg.github.io/keyboard-lock/), [Chrome API documentation](https://developer.chrome.com/docs/capabilities/web-apis/keyboard-lock), [Chrome permission update](https://developer.chrome.com/blog/keyboard-lock-pointer-lock-permission)

The existing owner decision stays open: [hotkeys.md](../../design/hotkeys.md) says F1 is never bound by default while its WASD layout uses F1–F4 with modifiers. Neither bindings, a remapping UI nor the desktop-shell claim were changed. Three-engine CI remains separate from manual native verification.

To inspect the harness manually, serve `apps/web/e2e/key-capture.html` from localhost in an isolated disposable browser profile. Focus the probe surface or input, request capabilities with the buttons, record browser/OS consequences separately in the operator-notes box, then download observations. Use a disposable profile because native close/reload/new-window/quit shortcuts can affect its browser UI. Automation-generated reports identify their input source and cannot be relabelled as physical-key evidence.
