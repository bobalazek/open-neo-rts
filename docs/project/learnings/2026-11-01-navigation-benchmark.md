# Navigation work is separate from full-match cost

`bun neo bench --workload navigation` measures 300 persistent unit request slots across eight Forces on the built-in `map:bench-river-256` (256×256), seed 1, foot radius 256 subcells. The map has an eight-cell-wide water barrier at columns 124–131, a shallow shoreline around its deep centre, and a sixteen-cell crossing at rows 120–135. Each slot alternates between columns 24 and 232; its row is derived from seed, entity ID and issue tick. Completed requests resubmit next tick. This is an **Addition — engineering benchmark fixture**, not authored game content or a full unit-following scene.

The existing `PathScheduler` shares exactly 4,096 node expansions per tick across Forces. The CLI times submission and search/scheduling, including lazy search allocation and returned partial paths. Bounds, passability, neighbour/corner traversal, reconstructed route cost, endpoint and request/expansion conservation are asserted outside the timer. The measured receipt includes a stable checksum of expansion counts, queue sizes and returned paths; the smoke check compares independent runs. One hundred warmup ticks precede 1,000 measured ticks. Reported duration is the sum of measured timed intervals. Map creation, cold compilation, scheduler setup, correctness checks and checksum calculation are excluded; cold compilation is reported separately.

On 2026-11-01, one final batch capture on an Apple M1 Max with 32 GiB RAM, macOS 27.0.1 (26A434), Bun 1.3.9 (cf6cdbbba), using this CLI change atop `4762acf`, reported **cold compile 167.219 ms**, then **mean 2.988 ms, p95 4.795 ms, max 9.058 ms** over 1,000 measured ticks (timed duration **2,988.009 ms**). It expanded **4,096,000 nodes**, exactly 4,096 per tick, submitted **733 requests (0.733/tick)**, served **8,733 partial/final results**, completed **734 requests**, and ended with **298 queued**, with checksum **`388e15fd`**. Two completed slots were ready for submission on the next tick. Counters cover only the measured interval; some completions belong to requests submitted during warmup. These are one headless local run's timings under ordinary desktop load, not a timing guarantee.

The existing `--workload flat` remains a separately labeled full-kernel movement/ECS benchmark. Navigation timings exclude unit following, string pulling, world hashing, rendering, projection and networking. They cannot establish the 12 ms full-match budget or the phase-1b browser frame-rate exit. No CI timing threshold is used.
