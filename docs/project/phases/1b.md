# Phase 1b: debug mode

How to pick, claim and finish a task: [README.md](./README.md). Standard checks and the simulation outcome rule: [README.md](./README.md#rules-for-every-task).

## Goal

From the [roadmap](../roadmap.md#phases): run the real sim in a browser worker, inspect it through a seat's projection, and use debug mode to test maps, existing content, placement and movement. Without this, later gameplay has no reproducible interactive test surface.

This expands the existing queue, not the game's scope. Docs this phase builds: [debug-mode.md](../../design/screens/debug-mode.md), [terrain-and-biomes.md](../../design/terrain-and-biomes.md), [structures.md](../../design/structures.md#placement), [rendering.md](../../engineering/rendering.md), [pathfinding.md](../../engineering/pathfinding.md), [assets.md](../../contributing/assets.md) and [testing.md](../../engineering/testing.md).

## Exit criteria

From the [roadmap](../roadmap.md#exit-criteria), unchanged:

> `bun run dev` opens [debug mode](../../design/screens/debug-mode.md) on every [sandbox map](../../design/terrain-and-biomes.md#sandbox-maps). Any unit or structure of any faction can be spawned, and placement rules (land, shore, water, node) hold. 200 units move and path on a 128×128 map with height levels at 60 fps (medium preset). Selection, box select, move and attack-move work. The renderer reads only the projection. Every tier-1 Eastern Collective unit and structure has a first-pass model. Playwright end-to-end tests (spawn, move, state hash) run in CI

Phase 1a's browser/CI gate remains separate. An accepted implementation or local pass does not prove either exit.

## Starting state and boundaries

Snapshot: 2026-11-01, through PR #125. Main contains the authored maps and all first-pass unit/structure/prop model references, the map-aware worker/debug client, authoritative spawning and occupancy, navigation and path following/repaths, model instances and idle/move animation, selection/orders, inspector/time controls, graphics presets, foundations and animated water. See [handoff](../handoff.md) for delivery and measurement limits.

Evidence is the source and tests named in each delivered task. Final repository/content/three-browser CI is batched on the assembled main commit. Overlays, reproduction exports, LOD and performance proof remain open; source delivery does not establish the phase exit.

- **Decided:** sim owns integer gameplay state and commands; renderer reads presentation data only. Maps and existing definitions are data. No gameplay dependency is added.
- **Needs owner decision:** node ownership/content blocks real node-bound placement. Build radius and clearance policy need concrete rules. These are tracked in [human-tasks.md](../human-tasks.md). The [movement-domain water table](../decisions/2026-11-01-movement-water-table.md) was accepted on 2026-11-01.
- **Delivered art:** all reviewed Alliance of Free Nations and Phoenix Initiative folders are merged, with strict presentation validation enabled. Art direction and roster sign-off remain pending; first-pass delivery does not replace either.
- **Out of scope:** economy, construction progress, production, damage/combat, bots, victory, multiplayer transport, full vision/stealth rules, hierarchical paths, flow fields, formations and fixed-wing flight. Attack-move gets its phase-1 order and movement behavior; target acquisition and fighting arrive with combat in phase 2.

**Flow to verify:** developer opens `/debug` → chooses a built-in map, seed and Forces → spawns an existing definition → selects it and issues an order → steps or runs the worker → reads projected state/hash → exports a scenario → reproduces its hashes with `bun neo run`. Invalid input, refused placement, absent assets and worker/load failure must produce a clear recoverable state. Reload replaces the session; late messages from the old worker cannot alter it. No account or online permission flow exists in this phase; command grants still apply to normal orders.

**Blast radius:** match setup and scenario parsing, definitions converted to integer units, command validation/grants, state serialization/goldens, worker lifecycle, renderer asset disposal and picking, map loading, camera input, browser tests and CLI benchmarks. Outcome-changing PRs update the simulation version and affected goldens together; old scenario versions fail explicitly rather than silently changing meaning.
