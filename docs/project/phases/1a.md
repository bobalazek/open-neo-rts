# Phase 1a: engine foundations

How to pick, claim and finish a task: [README.md](./README.md). Rules that apply to every task (standard checks, outcome rule): [README.md](./README.md#rules-for-every-task).

## Goal

From the [roadmap](../roadmap.md#phases): "engine foundations: deterministic math, ECS, tick loop, commands, movement, headless runs with golden hashes."

Docs this phase builds ([roadmap](../roadmap.md#what-each-phase-builds)): [architecture.md](../../engineering/architecture.md), [numerics.md](../../engineering/numerics.md), [testing.md](../../engineering/testing.md).

## Exit criteria

From the [roadmap](../roadmap.md#exit-criteria), unchanged:

> `bun neo run` plays a scripted 2-Force scenario for 10,000 ticks. Checkpoint hashes are identical across two runs in one process, two processes, and Chromium, Firefox and WebKit. `packages/deterministic` has golden tests for every function. CI runs all of this

Phase 1a and [phase 1b](../roadmap.md#phases) are one roadmap phase, so their tasks are picked together, 1a first.

### 1A-10 · Define the match setup and command log, and add `bun neo run`

- **Status:** done. `SIM_VERSION`, typed setup and fixed feature registration, strict versioned scenario parsing, shared pure runner and `bun neo run`, with parser, boundary and CLI tests. The 10,000-tick golden/browser suite remains 1A-11.
- **PR type:** tooling
- **Depends on:** 1A-08
- **Spec:** [testing.md §2](../../engineering/testing.md#2-determinism-harness), [saves-and-replays.md](../../engineering/saves-and-replays.md#what-gets-stored), [architecture.md §5](../../engineering/architecture.md#5-determinism-contract), [deployment-and-operations.md](../../engineering/deployment-and-operations.md#versions)
- **Scope:**
  - `SIM_VERSION`, an integer constant exported by `packages/sim` (starts at 1). It is what the outcome rule bumps.
  - The match setup type: seed, `debug` flag, Forces (index, faction), seats and their grants, and the definitions it uses (by ID). No map yet: the world is a flat, empty plane until 1B-17.
  - `createMatch(setup)`: creates a kernel and registers the features in one fixed order (entities, then movement), with the setup's grants.
  - The command-log file (a scenario): `{ format, simVersion, setup, commands }`, with `commands` in the canonical `Command` shape. A parser that rejects a wrong `format` or `simVersion` with a clear message and malformed files with the field that's wrong.
  - `bun neo run <scenario> [--seed N] [--ticks T]`: feeds each command at its tick, steps to the end (the last command's tick, or `--ticks`), and prints one `tick hash` line per checkpoint plus the final state hash. It runs the scenario twice in one process and fails if the two runs differ ([testing.md §2](../../engineering/testing.md#2-determinism-harness)).
  - **Not in scope:** content hashes and the map in the setup (2-01, 1B-17); comparing with goldens (1A-11); divergence reports (1A-12).
- **Files:** `packages/sim/src/match.ts` (new, exported from `packages/sim/src/index.ts`), `packages/sim/src/snapshots/` (command-log types and parser), `apps/cli/src/commands/run.ts`, `apps/cli/src/index.ts`, `CONTRIBUTING.md` (command table), `docs/engineering/architecture.md` (§3 CLI list)
- **Done when:**
  - Tests: the parser accepts a valid log and rejects each malformed case; `createMatch` registers features in a fixed order; `bun neo run` on a small test scenario prints the expected lines and exits 0.
  - Running the same scenario twice prints identical output.
  - Standard checks pass.

### 1A-12 · Report the first divergent tick

- **Status:** done on main through PR #48 (`d0fd2ca`). Trace/compare tests and browser failure artifacts are implemented and merged.
- **PR type:** tooling
- **Depends on:** 1A-10
- **Spec:** [testing.md §2](../../engineering/testing.md#2-determinism-harness), [architecture.md §5](../../engineering/architecture.md#5-determinism-contract) (developer event log)
- **Scope:**
  - `bun neo run <scenario> --trace <file>` writes the state hash of every tick, plus the event log, to a trace file.
  - `bun neo run --compare <trace-a> <trace-b>` prints the first tick whose hashes differ, the event-log entries of that tick in both traces, and a per-entity, per-component diff of the canonical state at that tick (re-running the scenario to it).
  - The browser determinism test (1A-11) writes a trace on failure and keeps it as a CI artefact.
  - **Not in scope:** fuzzing (2-41).
- **Files:** `apps/cli/src/commands/run.ts`, `packages/sim/src/snapshots/` (state diff), `apps/web/e2e/determinism.e2e.ts`, `.github/workflows/ci.yml`, `docs/engineering/testing.md`
- **Done when:**
  - A test with two deliberately different command logs reports the right tick, entity and component.
