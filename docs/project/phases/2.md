# Phase 2: first playable skirmish

Status: implementation authorized, 2026-11-02. The owner [changed sequencing](../decisions/2026-11-02-gameplay-before-performance.md) to build functional gameplay before completing performance acceptance, then [delegated provisional defaults](../decisions/2026-11-02-provisional-implementation-autonomy.md) rather than repeated approval questions. Preserve accepted scope/content and record missing choices for later polish; this does not declare phase 1b complete. Track original planning in [issue #144](https://github.com/bobalazek/open-neo-rts/issues/144) and follow functional dependencies in [README.md](./README.md).

## Goal and exit

Make the first real local match: Home → Skirmish → Loading → Match → victory or defeat → replay/rematch. The human and bot each control a Force through granted commands and visibility-filtered observations. Quick play reuses the skirmish setup and start path with the supported default matchup; it must not maintain a second match implementation.

The roadmap's candidate is an Eastern Collective tier-1 mirror on Training Grounds, by Last Man Standing. Its exit remains:

> A human beats or loses to the first bot in an Eastern Collective mirror on Training Grounds, by Last Man Standing, in 10–25 minutes. Every tier-1 Collective unit and structure is used. The replay reproduces the final hash. No crash in 20 AI-vs-AI matches across seeds.

The owner [approved that scope and the existing tier-1 numbers provisionally](../decisions/2026-11-02-first-playable-scope.md). A scripted victory, two units exchanging damage, an instant surrender or a passing command test cannot replace that exit. An AI-vs-AI run cannot be described as the human playtest.

## Reuse and boundaries

Reuse integer numerics/PRNG streams, ECS, command ordering/grants, terrain navigation, worker hosting, projections, existing first-pass assets, model/terrain presentation, selection and the scenario/CLI harness. Extend the real systems; do not create a parallel skirmish simulation or move sim ownership onto the UI thread.

`packages/content/src/loader/` resolves and validates packs and separates gameplay/cosmetic identity. `compileGameplayCatalog` in the sim's entity feature reuses `toDefinition` and converts the remaining gameplay quantities once. The debug catalog remains a preview registry, not a playable match or complete mod importer.

Canonical state belongs to each match: banks, power, ore/node remaining amounts, builder/site work, queues, orders, combat/projectile state, vision/ghost memory, bot PRNG/decisions, victory and statistics. Serialization, hashes and restore must include every outcome-affecting field. Timing, audio, UI preferences, particles and interpolation stay outside that state. AI sees the same permitted observation as a human and emits next-tick commands with counted work budgets.

The browser storage boundary owns profile/settings, saves and replay files. Imported files are untrusted: validate format/sim/content/map identity and bounded payloads before replacing a session. A failed load preserves the current match. Server transport, online rooms, reconnect and Shared Command integration belong to phase 3; accounts, ranked play and voice remain later roadmap work. Full training missions, campaign triggers, the map editor and other victory modes remain in their assigned phases.

Screens follow their existing [wireframes and states](../../design/screens/README.md), [UI style](../../design/ui-style.md) and locale rules. Fill the documented feature folders; keep `apps/web` as wiring. The current terrain view at `/` needs an explicit retained debug entry when Home takes that route.

## Dependency path and delivery order

```text
accepted scope + required functional foundations
  └─► content/rules/starting kit ─► bank/power/harvesting
                                ├─► builders/sites ─► production/rally
                                ├─► vision ─► permitted observations/events
                                └─► weapons/projectiles/damage ─► deaths/wrecks
economy + production + combat + vision ─► first bot ─► AI-vs-AI runner
setup + worker + projections ─► skirmish/loading ─► HUD/minimap/menu
canonical state + content identity ─► save/restore/replay
all delivered systems + original audio/help/editor slice
  └─► browser flows + 20-seed matches + human match + replay hash ─► exit
```

Default to one substantial task per branch and PR; small related tasks may share a PR. Land each reviewed PR as one squash commit ([delivery policy](../decisions/2026-11-03-coherent-delivery-batches.md)). Use small regressions for new outcome logic, then repository/content/browser validation at batch boundaries as requested by the owner. Do not repeat a full suite for every model or edit. Every sim outcome change bumps `SIM_VERSION` and updates affected goldens. Keep CLI file I/O and wall-clock measurement outside deterministic packages.

Tasks remain subject to their listed gameplay decisions and functional dependencies. Performance acceptance no longer blocks independent gameplay work. Sizes are effort bands; confidence is medium until the content decisions and compiled gameplay contract are settled. Each **Done** item includes relevant refusal/cancellation/reload behavior, not only the happy path.

## Acceptance and unresolved scope

The phase is complete only when the actual roadmap exit, UI/playback/persistence obligations and required tier-1 behavior are evidenced. Keep original asset production as individual art tasks and split L-sized tasks before coding if the reviewed contract crosses independent deliverables; a task heading is not permission for a giant mixed-type PR.

Blast radius: canonical setup/content identity, commands/grants, all feature serializers/goldens, projection/fog boundaries, worker lifecycle, navigation occupancy, renderer model/event ownership, browser storage, AI observations/next-tick commands, UI routes/input and original audio assets. Compare against the delivered phase-1b debug/CLI paths so the new playable route cannot silently break them.

Phases 3–5 remain the roadmap's full objective: online 1v1 and 2v2 Shared Command/reconnect and the completed Eastern Collective; three-faction expansion, editor/objectives/training/campaign; then multiplayer services, desktop and release. This first-playable plan neither replaces those requirements nor claims to deliver them.
