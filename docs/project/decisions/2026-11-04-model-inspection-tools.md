# Model-first content inspection

Phase-2 task 2-38 begins with model inspection, as the screen specification
requires. The larger editor/playtest scope is retained in named 2-38b/c/d tasks:
schema-derived editing and safe saves, validated draft playtests/effects, and
asset editing/gizmos. This batch does not replace those requirements with a
read-only tool or claim the whole editor complete.

## Fit and behavior

`/tools/content` reuses the installed 137-definition registry and original models.
It joins the existing Home developer footer; the current development and
production-preview builds expose that footer alike. Release access policy
remains with the later release work.

The native Babylon pane uses the established graphite controls. The model leads
on the desktop left and sits above controls on narrow viewports. Search accepts
names and installed IDs. `?model=` accepts an installed qualified ID or its exact
registered model URL; unknown values show recovery without fetching remote URLs.
Open and Retry stay in the pane footer; file/kind help is contextual, and the
pane honors the saved interface scale.

Open local GLB and canvas drop accept self-contained files up to a provisional
16 MiB. The viewer does not write content, record authorship or upload files.
The local file's validation kind is editable; installed definitions retain their
actual kind and authored requirements. Failure retains the last successfully
loaded model, clip controls and its diagnostics. Retry repeats the failed source.
Successful local loads clear the installed-definition selection.
Pending fetches are aborted and stale loads disposed on replacement or exit.

Team choices exercise actual standard team material slots. The animation picker
plays actual installed clips; rest is the default. LOD uses the renderer's
existing unambiguous disjoint-branch masks and provisional 96-metre threshold.
Zoom can reach that threshold even for small models; forced controls are disabled
when no supported pair exists. Damage-state inspection enables `state_damaged`
below 66% and also `state_critical` below 33%, preserving independent LOD masks.
These are presentation previews, not simulation health edits or complete combat
effects.

## Validation boundary

The CLI and viewer share the existing exported `modelRequirements` and
`validateModel` functions. Installed assets use their actual definition; generic
local assets use the chosen kind's common requirements. Errors/warnings remain
visible while a structurally renderable model can still be inspected. This is
project model validation, not complete pack/reference or external glTF conformance
validation. Full save-time checks remain in 2-38b.

Materials, nodes and sockets are actual parsed inventories, displayed in native
expandable tables with the existing keyboard scroll bridge. Lists show at most
100 entries and disclose that cap; the full diagnostic count remains visible.
The shared panel gains an explicit rich-content scope instead of coupling this
tool to match-result markup. Existing panel consumers retain their behavior.
Nested table viewports fit the available pane, and panel dirty-rectangle
optimization is disabled after a reproduced clipped-text failure when scrolling.

## Evidence and limits

Unit checks compare original Dragon Tank requirements with the CLI validator and
cover missing sockets, allowlisted links, malformed bytes and the file-size cap.
Browser checks exercise native team selection and painted inventories, actual
model color/clip/LOD/damage changes, nested damage under LOD, reachable Auto LOD,
unpaired branches, file/drop loading, failed-file retention and URL recovery.
Synthetic geometry is labeled as a test fixture; visual review uses original art.
Existing Home and paused Field Manual checks cover the shared renderer/panel
callers. SIM59 and gameplay outcomes are unchanged; no new dependency or authored
content asset is introduced.

Physical file dragging, hardware performance and Firefox remain separately
unqualified. Hosted CI capacity remains an owner task. Definition forms, source
editing, safe writes/downloads and conflicts, unsaved draft playtests, grid/scale
reference, socket gizmos, mapped-material editing, weapon effects/destruction and
remaining documented controls stay open in the named follow-up tasks.
